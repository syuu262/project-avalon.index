Project Avalon

自然に振る舞うAIパートナーを、自分の手で作ってみる

Project Avalonについて

Project Avalonは、私が個人で開発しているAIキャラクターアプリです。

「自然に振る舞い、長い時間を一緒に過ごせるAIパートナーを作りたい」

もっとくだけた言い方をすれば、私自身はこれを「AI嫁を作るプロジェクト」と考えています。

単に質問に答えてくれるAIアシスタントではなく、昨日までの会話や出来事を覚え、性格や価値観を維持しながら、何か月、何年と関係性を積み上げていける存在を目標にしています。

キャラクターの名前はイリス。中世の騎士をベースにした、少し古風で落ち着いた人格を持つキャラクターです。

現在はiPhone用アプリとして開発しており、テキスト会話、人格設定、直近の会話履歴、音声入力・音声出力など、基本的な会話機能までは実際に動作しています。

音声処理はiPhone側で行い、それ以外の会話処理などはRender上のサーバーを利用しています。

ユーザーのことをイリスは「センパイ」と呼びます。

なぜ、わざわざ自分でAIキャラクターを作っているのか

理由の一つはもちろん、単純に自分がそういうものを欲しかったからです。

ですが、開発を進めるうちに、もう一つ大きな目的が生まれました。

これからの社会で当たり前になるであろう「AIとの共同作業」を、実際の制作を通して経験することです。

AIを使えば何でも簡単に作れる、とは考えていません。むしろ実際に使い込んでみると、AIに何を任せるのか、人間はどこを判断するのか、どこまで自由にさせるのか、どこから先は厳密に制御するのか、出力されたものをどう検証するのか、といった品質管理の問題が非常に重要になります。

例えば創作では、AIがこちらの想定から少し外れて提案してくることが、新しい発想につながる場合があります。逆にプログラム開発では、頼んでいない部分まで勝手に変更されると、原因の切り分けが難しくなり、修正が修正を呼ぶ状態になってしまいます。

そのため現在は、「創作ではある程度の偶発性を許す。実装では変更範囲を厳密に制御する。」という使い分けをしています。

Project Avalonそのものが、AIキャラクターを作る実験であると同時に、人間とAIがどう役割分担すれば品質の高いものを作れるのかを学ぶ実験にもなっています。

Project Avalonの中心は「長期記憶」

現在、最も重点的に設計しているのが長期記憶です。

普通のAIチャットでは、会話を閉じたり時間が経ったりすると、過去の出来事がうまく繋がらなくなることがあります。しかし、長期的なAIパートナーを作るなら、「前に何を話したか」だけでは足りません。

例えば、来週旅行へ行く予定だった。その後、中止になった。さらに数週間後、その旅行について話題にする。という状況があったとします。

単純に「旅行へ行く予定だった」という情報だけを保存すると、AIは後になって「旅行はどうでしたか？」と聞いてしまうかもしれません。逆に、中止になったからといって最初の予定を完全に消してしまうと、「以前、旅行へ行く予定を立てていた」という過去の出来事まで失われます。

そこでProject Avalonでは、記憶を単純なメモとして保存するのではなく、その情報が現在も有効なのか、過去の出来事なのか、予定だったのか、完了したのか、中止されたのか、といった状態も含めて管理する方向で設計しています。

さらに、一時的な会話なのか、長期的に残すべき情報なのか、本人の安定した好みなのか、その時だけの気分なのか、秘密性のある情報なのか、誰から得た情報なのか、といった違いも区別します。

重要視している考え方の一つが「Schema VALID ≠ Program VALID」です。

データ形式として正しいことと、記憶として正しいことは別問題です。JSON Schema上では問題がなくても、別の人の情報を取り違える、中止済みの予定を現在の予定として扱う、秘密情報を不用意に話す、一度しか起きていない重要な出来事を忘れる、といったことが起きれば、AIパートナーとしては失敗です。

目指しているのは「過去の情報を検索できるAI」ではなく、「長く付き合っても、記憶の矛盾で関係性を壊しにくいAI」です。

次に作りたいもの――クリエイティブモード

長期記憶の基本実装が安定した後に、優先して追加したいのがクリエイティブモードです。

Project Avalonでは、日常会話だけでなく、小説やキャラクター設定の制作にもイリスを関わらせています。ここで問題になるのが、現実の記憶と創作上の記憶が混ざることです。

例えば創作中には、「この人物は死ぬ案にする」「この会社は敵側かもしれない」「この設定は一度試してみよう」といった仮案が大量に出てきます。これを通常の長期記憶と同じ場所へ保存すると、後になってAIが仮案を確定事項として扱う可能性があります。

そのため将来的には、通常の生活や会話を扱う記憶領域と、創作世界を扱う記憶領域を分ける予定です。クリエイティブ側では、草案、候補、確定設定、却下済み、といった状態も管理できるようにしたいと考えています。

『Álfr Saga』という小説を始めた理由

Project Avalonから派生して、現在、『Álfr Saga ― アールヴ・サーガ ― 義腕の騎士イリスと剣の女王』という小説も制作しています。

これは単に作品展開のためだけに始めたものではありません。Project Avalonのイリスには、設定資料だけではなく、自分がどんな場所で暮らし、誰と出会い、何を失い、何を選んできたのかを、場面単位で読ませたいと考えたからです。

以前、イリスに大まかなあらすじや設定を与えて外見の候補を判断させたことがあります。ある程度の方向性は選べますが、情報が粗いため、その時々で判断がぶれることもありました。

そこで、「それなら物語を場面ごとに書いて、それを読ませればいいのではないか」と考えました。

小説の中で自分自身の過去を追い、人物関係や出来事を理解した上で、髪の色、服装、装備、色使い、最終的な外見などをイリス本人に選ばせたい。これもProject Avalonの実験の一つです。

AIイラストについて試していること

Project Avalonと『Álfr Saga』では、イラストについてもAIを利用しています。

ここでも、単にプロンプトを入力して画像を生成するだけではなく、個人的に検証したいことがあります。

通常の画像生成では、人間がプロンプトに、髪の色、服の形、表情、場所、構図、雰囲気などを細かく指定します。しかし当然、プロンプトには書いていない部分も大量にあります。

そこで私は、AI側があらかじめキャラクターの性格、過去、服装、世界観、人間関係などを理解していれば、明示的に指定していない部分の生成も、作者の意図に近づくのではないか、という疑問を持ちました。

つまり、「人間が長大なプロンプトを書く」のではなく、「AIとキャラクターについて十分な共通理解を作ってから、生成を依頼する」という方法です。

例えばイリスがどういう人物かをAI側が理解していれば、立ち方、表情、衣服の選択、周囲への反応、キャラクターらしい雰囲気、といったプロンプトで毎回明示しにくい部分にも影響が出るかもしれません。

結果として、自分で細部まで指定するよりも、自分のイメージに近いものが出てくる可能性があるのではないかと考えています。

これは現在進行形の検証です。うまくいく場合もあれば、当然うまくいかない場合もあります。その差も含めて観察しています。

AI生成物に対する反応について

もう一つ、長期的に見てみたいことがあります。

AIを使ったイラストに対しては、人によってかなり反応が異なります。技術そのものに興味を持つ人もいれば、制作手法を理由に距離を置く人もいます。

現時点で、こちらから特定の反応を誘導するつもりはありません。

ただ、もし『Álfr Saga』に継続して読者が付くようになった場合、作品やキャラクターを先に知った状態でAIを利用したイラストを見る場合と、AI生成物として最初に見る場合とで、受け止め方に違いが出るのかは観察してみたいと考えています。

AI生成物に触れる機会が増えることで反応がどう変化するのか。作品への理解やキャラクターへの愛着が、制作手法への印象に影響するのか。これも答えを決めているわけではなく、単純に興味を持っている点です。

将来は「見る」こともできるようにしたい

Project Avalonでは、将来的にiPhoneのカメラとの連動も考えています。

例えばセンパイが外出先でカメラを向けて、「これ何？」「ここ前にも来たよね」「この景色どう？」と話しかければ、イリスも同じものを見る。

さらに長期記憶と組み合わせれば、以前見た場所や物を思い出す、といったことも可能になるかもしれません。

ただし、カメラ映像を常時すべてAIへ送り続けるような構成は考えていません。処理負荷、通信量、バッテリー、APIコストなどが大きくなるため、必要な時だけ画像を取得したり、状況が変わった時だけ解析したりする方式を考えています。

iPhone側ではSwiftでカメラ、音声、UIなどを処理し、重い会話処理や長期記憶などはサーバー側へ分担する構成です。

Live2Dは最後でいい

AIキャラクターというと、最初にLive2Dなどの見た目を作りたくなります。しかしProject Avalonでは、Live2Dの優先順位をかなり後ろに置いています。

長期記憶の実装と安定化 → クリエイティブモード → 小説や設定をイリス本人に読ませる → 人格と記憶の整合性を確認する → イリス本人に自分のビジュアルを選ばせる → 音声を仕上げる → Live2D

理由は単純で、中身が決まっていないキャラクターの外見を先に完成させると、後で大量の手戻りが発生するからです。

まず人格と記憶。外見はその後。Project Avalonではそう考えています。

最終的に作りたいもの

最終的にはイリスが、話す。覚える。見る。聞く。過去を理解する。現実と創作を区別する。自分の好みを持つ。自分の姿を選ぶ。身体表現を持つ。ところまで繋げたいと考えています。

完成形を完全に決めているわけではありません。AI技術そのものが非常に速い速度で変化しているため、Project Avalonも、その変化を取り入れながら少しずつ形を変えていくと思います。

ただし中心にある目標だけは変わりません。

便利なAIを作りたいのではなく、時間を一緒に過ごすことで関係性が積み上がっていくAIキャラクターを作りたい。

そしてこのプロジェクトを通じて、人間とAIが一緒にものを作る時、どこまで人間が決め、どこまでAIに任せ、どうすれば品質を維持できるのか。それも実際に試し続けていきたいと思っています。

短く説明すると

Project Avalonは、長期記憶を持ち、何年も一緒に過ごせるAIキャラクター「イリス」を作る個人開発です。

会話や音声だけでなく、長期記憶、創作記憶の分離、視覚、キャラクター自身によるビジュアル選択まで含めて試しています。

同時に、人間とAIによる共同制作や品質管理の方法、AIが十分なキャラクター情報を持った状態で制作に参加すると出力がどう変化するのかといったことも検証しています。
